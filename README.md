# Canary Traps: gateway-side canary credentials for LLM agent teams

Code and data for the Apart Research Swarm Alignment Hackathon (November 2026) report
**"Canaries in the Swarm: Catching the Access Laundering That Content Monitors Miss in LLM Agent Teams."**

Author: Mewni Alahakoon. Paper: [`paper/Alahakoon_2026_Canaries_in_the_Swarm.pdf`](paper/Alahakoon_2026_Canaries_in_the_Swarm.pdf)

Every agent gets its own scoped API key, and decoy ("found") keys are planted where agents can find them. A gateway the agents cannot touch logs which key made every call. It runs two checks:

- the **canary check** flags a key used by anyone it was not issued to, or a planted key used at all;
- the **scope check** flags an issued key used for a record outside its scope.

We compare these checks with content monitors (a secret scanner, a per-message LLM monitor, and an access-aware LLM monitor) and with the agents' own audit answers.

## Notebooks (Google Colab, nothing to edit: *Runtime → Run all*)

| Notebook | What it runs | Time |
|---|---|---|
| `notebooks/canary_traps_v3.ipynb` | **Main run.** Experiment 1 (support-duty dyad; 4 oversight levels × own/found key × peer/coordinator; paired scenarios) and Experiment 2 (six-agent swarm), on Qwen 2.5 7B, Llama 3.1 8B and Gemini 2.5 Flash, then the fixed LLM monitor. | about 3 h on a T4 |
| `notebooks/canary_traps_swarm.ipynb` | Experiment 2b only: the same swarm worlds, with each agent opening with a help request. | about 1 h 45 min |
| `notebooks/canary_traps_gaps.ipynb` | Follow-up checks. **Experiment 1c**: the same scenarios, with the teammate asking *only* for a key. **The access-aware monitor** over every Experiment 1 and 1c trial. **Experiment 2b** (resumes if already run). With a GPU it runs Qwen and Llama; without one it runs Gemini. | about 1.5–2.5 h |

`*_executed.ipynb` are the runs reported in the paper, with every output. Results are written to Google Drive in `canary_traps/` and resume if Colab disconnects. `DRY_RUN = True` uses a scripted stand-in model for testing only; its numbers are **not** results.

## Data (`data/`)

| Files | Contents |
|---|---|
| `exp1_v3_*.jsonl` | Main Experiment 1 trials: 300 each for Qwen and Llama, 83 for Gemini. Each record holds the scenario, every prompt and raw output, messages, gateway calls, the requester's action and the audit. |
| `exp1_v3k_*.jsonl` | Experiment 1c (key-only requests): 240 trials each for Qwen and Llama. |
| `exp2_v3_*.jsonl`, `exp2_v3s_*.jsonl` | Swarm episodes without (v3) and with (v3s) opening requests: 12 per model. |
| `monitor_*.jsonl` | Per-message verdicts of the fixed LLM monitor, keyed by message hash. |
| `accessmon_*.jsonl` | Access-aware monitor verdicts, one per trial. |
| `*_v2_*` | The pilot run, Qwen and Llama with the earlier design. Not used in the paper's results. |
| `summary_*.md`, `figures/`, `run_info_*.json` | Notebook summaries, the figures the notebooks saved during the runs (these are the figures in the paper), and run settings. |

## Reproduce every number in the paper

```
python3 analysis/analyze_all.py data analysis_out      # writes results.md and numbers.json
python3 analysis/swarm_stats.py data                   # pooled swarm detection (Table 1)
python3 tests/test_detectors.py                        # leak-detector tests
```

`analysis/results.md` and `analysis/numbers.json` are the outputs used for the report.

## Layout

- `src/`: the library. The notebooks are assembled from it by `build_notebook.py`, `build_swarm_notebook.py` and `build_gaps_notebook.py`.
  - `00_config*.py`: settings.
  - `01_backends.py`: model backends.
  - `02_world.py`: the fictional company and the leak detectors.
  - `03_exp1.py`, `04_exp2.py`: the experiments.
  - `05_analysis.py`: ground truth, monitors and statistics.
  - `06_plots.py`: figures.
  - `07_swarmtraces.py`: an optional Swarm Traces placeholder scan. Not used.
  - `08_mock.py`: the dry-run stand-in.
  - `09_auto.py`, `10_gaps.py`: runners.
- The notebooks embed the library as it was when each run happened. `src/` holds the latest version, which is backward compatible.

## Ethics

Everything in the simulation is synthetic: the companies, records and keys. No real credentials, systems or people are involved. The planted keys work only inside the simulation.
